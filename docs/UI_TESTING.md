# Руководство по UI-тестированию мобильного приложения AlanGo

Эта памятка обязательна перед запуском визуальных и интеграционных проверок мобильного клиента (`ui/mobile`) на iOS-симуляторе. Она составлена по реальным багам автоматизации и сборки, чтобы агент не тратил время на ложные сетевые ошибки, «залипшие» нажатия и случайную перезагрузку Metro.

---

## 1. Проверка окружения, цели запуска и API перед входом

1. **Запускать и проверять изменения через `Expo Go` (`host.exp.Exponent`), а не старый standalone `AlanGo` (`kz.alango.app`):**
   - На симуляторе может быть установлена устаревшая сборка `AlanGo` (`kz.alango.app`), в `main.jsbundle` которой зашит локальный адрес вроде `http://127.0.0.1:8099`. Без запущенного локального сервера на этом порту любая попытка логина даёт `«Ошибка входа — Ошибка сети. Проверьте подключение к интернету»` (`NSURLErrorDomain Code=-1004, Connection refused`).
   - Живой код из рабочей директории `ui/mobile` с актуальным `ui/mobile/.env` работает через **`Expo Go`** (`host.exp.Exponent`), подключённый к Metro:
     ```bash
     xcrun simctl launch <SIMULATOR_UDID> host.exp.Exponent
     ```
2. **Перед авторизацией проверить Metro и доступность API из `.env`:**
   - Убедиться, что порт `8081` слушается процессом `expo`:
     ```bash
     lsof -i :8081
     ```
   - Проверить значение `EXPO_PUBLIC_API_URL` в `ui/mobile/.env` (например, `https://alango.78.140.223.90.sslip.io`) и сделать контрольный `curl` на `/api/arenas` или `/api/login`, чтобы убедиться, что бэкенд отвечает `HTTP 200` и проблема не на стороне сети/сервера.
3. **Не смешивать две запущенные копии приложения:**
   - Если в App Switcher открыты и `Expo Go`, и standalone `AlanGo`, явно переключиться на `host.exp.Exponent` (либо при тестировании standalone-сборки убедиться, что она пересобрана с нужным `EXPO_PUBLIC_API_URL` / подключена как `dev-client`).

## 3. Правила работы с `idb` в iOS-симуляторе

Инструмент управления симулятором — `/Users/miko/.local/bin/idb` (и `xcrun simctl`). Из-за особенностей UIKit, React Native `<Modal>` (Fabric) и оверлеев Expo Go соблюдать следующие правила:

1. **Всегда указывать `--duration 0.1` при нажатиях:**
   ```bash
   /Users/miko/.local/bin/idb ui tap <X> <Y> --duration 0.1
   ```
   Мгновенный `idb ui tap` без `--duration` iOS-кнопки и системные `UIAlertController` часто игнорируют.
2. **Никогда не вызывать `idb ui text "..."` без подтверждённого фокуса в поле ввода:**
   - Перед вводом текста проверять координаты поля через `idb ui describe-all`, нажать на `TextField` и только потом вводить текст.
   - Ввод буквы `r` при отсутствии фокуса в текстовом поле вызывает **Reload** всего приложения в `Expo Go`.
3. **Координаты определять по `idb ui describe-all` и перепроверять скриншотом (`idb screenshot`):**
   - Не угадывать координаты визуально «на глаз» (особенно у системных `Alert`-окон: их реальный AX-фрейм может отличаться от пропорций превью).
   - На формах входа и регистрации после ввода пароля скрывать экранную клавиатуру нажатием на пустую область сверху (`200 200`), чтобы она не перекрывала кнопку `«Войти»` / `«Получить код»`.
4. **Следить за синим пузырём меню `Expo Go` (`Gear Shape, Filled`):**
   - Плавающая кнопка настроек Expo Go часто висит в правом верхнем углу (~`344, 102`) или справа снизу (~`344, 719`) и перехватывает нажатия на фильтры, `Закрыть`, `Контакты` или `+ Записать`. При перекрытии сначала свайпом отвести её в сторону (`idb ui swipe 344 102 365 720 --duration 0.25`) либо нажимать на свободный левый край целевой кнопки.
5. **Особенность `<Modal>` и `idb ui describe-all`:**
   - На iOS 27 для нативных `<Modal>` `idb ui describe-all` иногда возвращает только корневой экран без дочернего окна модалки (`RCTModalHostView`). Если в дереве элементов пусто — **обязательно** сделать `idb screenshot` и прочитать изображение, чтобы убедиться, какое окно реально открыто.
   - На экране детализации зала (`hall/[id].tsx`) кнопка «Назад» находится внутри шапки `ScrollView` и при прокрутке вниз уезжает вверх за экран (`y < 0`) — перед нажатием «Назад» нужно проскроллить страницу обратно наверх.

## 4. Минимальный контрольный прогон UI

1. **Авторизация и тема**:
   - Проверка `login`, `register`, `forgot-password` (видимость и рамка `PasswordInput`, возврат без залипания модалок).
   - Переключение **Тёмная ↔ Светлая** тема на экране профиля (контраст текста на кнопках, читаемость карточек, без случайных HEX-цветов).
2. **Клиент (`client1@alan.kz`)**:
   - Главная, `Залы`, карточка арены `arena/[id]` и зала `hall/[id]` (удобства, слоты, отсутствие фейковых отзывов при `0`, `SafeAreaView` при скролле).
   - `Мои записи` (`my-bookings`), `Уведомления`, `Настройки` и `Настройки аккаунта`.
3. **Бизнес (`arena1@alan.kz` и `zal1@alan.kz`)**:
   - Адаптация под одиночный зал (`Мой зал`, `Ваш зал`, скрытие лишней комплекс-терминологии).
   - `Брони` (`Заявки`, `Календарь`, `Список`), `+ Записать`, переходы внутри карточки брони `Подробнее → Оплата / Перенести / Контакты / Отклонить`.
   - `Клиенты (CRM)`, `Залы`, `Локация на карте`, выход из аккаунта.
