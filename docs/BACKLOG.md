## 🗺️ Ключевой приоритет: Интерактивная карта («Залы рядом») — [x] Реализовано

### 📍 Экран «Залы рядом» для обычного пользователя (Игрока)
* **Статус**: ✅ **Реализовано** ([`ui/mobile/app/map.tsx`](file:///Users/miko/MyProduction/AlanGo/ui/mobile/app/map.tsx), точка входа в [`ui/mobile/app/(tabs)/index.tsx`](file:///Users/miko/MyProduction/AlanGo/ui/mobile/app/(tabs)/index.tsx)).
* **Пользовательский сценарий**: Обычный пользователь (аккаунт игрока / арендатора) в верхней части главного экрана видит кнопку / баннер «Залы рядом на карте». При нажатии открывается полноэкранная интерактивная карта спортивных площадок города.
* **Функционал экрана карты**:
  1. **Интерактивная подложка карты**: Интерактивная векторная карта на базе Leaflet + CartoDB Voyager с поддержкой жестов (зум, панорамирование).
  2. **Кластеризация маркеров**: При отдалении масштаба близлежащие спортивные комплексы объединяются в круглые кластеры со счетчиком (`2`, `3`, `5`, `9`, `12` и т.д.) в полном соответствии с референсом.
  3. **Пин-поинты и ценовые бейджи**: При приближении отображаются ценовые бейджи в виде речевых бабблов (например, `от 8 000 ₸`, `от 12 000 ₸`).
  4. **Геолокация**: Кнопка «Моя геопозиция» в правом верхнем углу для мгновенного центрирования карты на пользователе с пульсирующим маркером.
  5. **Контролы масштабирования**: Кнопки `+` и `-` в левом верхнем углу.
  6. **Карточка зала по тапу**: При нажатии на метку или ценовой бейдж снизу плавно выдвигается карточка площадки (BottomSheet) с фотографией, названием, рейтингом, адресом, ценой и кнопкой «Посмотреть залы и бронь».
  7. **Фильтрация на карте**: Горизонтальный скролл чипов по видам спорта (Все залы, Футбол, Баскетбол, Теннис, Волейбол, Падел / Сквош).

## 💳 Управление бронями: Редактирование записи и учет оплаты — [x] Реализовано

### 📍 Редактирование брони и частичная / полная оплата (Предоплата, 100%)
* **Статус**: ✅ **Реализовано** ([`ui/mobile/app/business/bookings.tsx`](file:///Users/miko/MyProduction/AlanGo/ui/mobile/app/business/bookings.tsx), [`ui/mobile/components/EditBookingModal.tsx`](file:///Users/miko/MyProduction/AlanGo/ui/mobile/components/EditBookingModal.tsx), [`ui/mobile/components/PaymentModal.tsx`](file:///Users/miko/MyProduction/AlanGo/ui/mobile/components/PaymentModal.tsx)).
* **Пользовательский сценарий**: Владелец площадки / администратор может редактировать подтвержденную запись в любой момент (перенос времени, зала, смена клиента, цены), а также вести учет оплаты (предоплата 2 000 ₸, 10 000 ₸ из 20 000 ₸, или 100% закрытие) с расчетом остатка.
* **Функционал**:
  1. **Индикатор оплаты**: Наглядные бейджи на карточках (🟢 Оплачено 100%, 🟠 Предоплата с расчетом остатка, ⚪️ Не оплачено).
  2. **Быстрое управление оплатой**: Модальное окно `PaymentModal` с кнопками «100%», «50%», «Предоплата 2 000 ₸», «Сброс» и полем произвольной суммы.
  3. **Полное редактирование записи**: Модальное окно `EditBookingModal` (клиент, телефон, зал, дата, время, цена, оплата, статус, заметки).
  4. **Учет предоплаты при создании**: В `ManualBookingModal` добавлена фиксация платежа при записи.

## 💡 UX / UI и Продуктовые улучшения

### 1. Календарь «Месяц — Неделя»
* **Контекст**: Календарь бронирований и расписания.
* **Требование**: Добавить удобный переключатель между режимами «Месяц» (компактная сетка 7x5 с цветовой индикацией загруженности дней) и «Неделя» (таймлайн по дням недели с почасовыми слотами).
* **Польза**: Быстрая навигация для администраторов комплексов и пользователей при планировании игр.

### 2. Организация медиа: Баннер сверху, галерея ниже
* **Контекст**: Экран детальной карточки спортивного комплекса / зала.
* **Требование**: Закрепить главный Hero-баннер (основное фото площадки) в верхней части экрана, а под ним разместить горизонтальную или сеточную фотогалерею дополнительных ракурсов (раздевалки, покрытие, трибуны, освещение).
* **Польза**: Повышение конверсии в бронирование за счет визуальной демонстрации инфраструктуры.

### 3. Детализация спецификаций в карточке поля
* **Контекст**: Просмотр характеристик площадки (`arena/[id].tsx` и `hall/[id].tsx`).
* **Требование**: Отображать четкие параметры:
  - **Количество полей** в комплексе.
  - **Тип и размерность**: Крытые / Открытые (с указанием точного числа каждого типа), размеры площадки.
  - **Вместимость / формат**: Рекомендуемое количество игроков (например, 5x5, 7x7, 11x11).
  - **Инвентарь и удобства**: Наглядные бейджи — наличие душа (раздевалки), выдача мячей, манишек (манежки).
* **Польза**: Пользователь сразу видит, подходит ли площадка для его команды и нужно ли брать с собой мячи/манишки.

### 4. Расписание: Разбивка по полям и времени
* **Контекст**: Экран расписания для комплексов с 2+ полями.
* **Требование**: В расписании реализовать наглядную матрицу/колонки:
  - Разделение по конкретным полям («Поле 1 (Крытое)», «Поле 2 (Открытое)» и т.д.).
  - Почасовая сетка времени с четким статусом каждого слота (Свободно / Забронировано / Недоступно).
* **Польза**: Исключение овербукинга и путаницы между параллельными тренировками на разных полях.

## 🐛 Багфиксы и Стабильность (Кабинет Бизнеса)

### 6. Восстановление блока выбора фото (Бизнес)
* **Симптом**: В форме создания / редактирования площадки и залов бизнеса пропал компонент выбора фотографий из галереи устройства.
* **Решение**: Проверить вызовы `ImagePicker.launchImageLibraryAsync`, permissions (разрешения на доступ к медиатеке), а также рендеринг сетки загруженных превью.

### 7. Обновление тарифа (Заявочная система с подтверждением) — [x] Реализовано
* **Требование**: При выборе нового тарифа отправлять заявку на бэкенд, показывать статус ожидания подтверждения и предоставить API для последующего одобрения администратором в админ-панели.
* **Статус**: ✅ **Реализовано** (Клиентский API `POST /api/subscription/request`, админские API `GET /api/admin/subscription-requests`, `POST .../approve`, `POST .../reject`, баннер в профиле).

### 8. Главный экран Бизнеса: Ошибка редиректов (Заявки)
* **Симптом**: На главном экране кабинета бизнеса при попытке перехода в раздел «Заявки» возникает ошибка маршрутизации / циклический редирект.
* **Причина**: Конфликт роутов в `ui/mobile/app/business/index.tsx` / `_layout.tsx` или некорректная проверка роли/прав владельца.
* **Решение**: Провести ревизию маршрутизации, исправить обработку нажатия на карточку «Заявки» и устранить зацикливание.
